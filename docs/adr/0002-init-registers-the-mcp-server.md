# init registers the MCP server, and the server says it is up

Setting up the MCP server was manual and silent: `init` printed a command to register by hand, and over stdio the server wrote nothing until a tool was called, so neither the person nor the agent's MCP log could tell whether it had found the Workspace.

**init writes the agent config.** This narrows ADR 0001's "init writes Workspace files only": `init` adds or replaces the `archidocs` entry in the repo-root `.mcp.json` (`mcpServers`), which Claude Code, VS Code and Copilot all read. It also updates `.cursor/mcp.json` (`mcpServers`) and `.vscode/mcp.json` (`servers`, with `type: stdio`) when that file already exists, and creates neither. Other servers are kept, and the file is rewritten as 2-space JSON; a file that is not plain JSON (such as JSONC with comments) is left alone and the entry is printed to paste. The entry runs the command ADR 0001 picks. `init --skill` writes config only when `--workspace` names the checkout. User-level configs are out of scope: `init` writes only inside the repo.

**The server announces itself on stderr.** Every client shows an MCP server's stderr in its MCP log, so stderr is the one channel; MCP `logging` notifications are not used. The server answers the client at once, then loads and checks its source in the background and prints one line: the version, transport, Workspace or Bundle, counts, check results and whether writes are on. A source that fails to load is reported on that line and is not fatal; tools return `source_unavailable` until it loads. Each write tool call logs one line with its outcome; reads log only with `ARCHIDOCS_LOG=debug`. The server reports the CLI's version to clients.

**`archidocs mcp … --check` is the health check.** It takes the same arguments as the registered command, runs the server in-process behind an in-memory client, and does `initialize`, `tools/list` and `list_teams`. It prints the startup line and the tool count, then exits 0, or 2 with the reason. It tests its own arguments only and never reads `.mcp.json`, so it never starts a command from a config file. `init` prints the `--check` line that matches the entry it wrote.
