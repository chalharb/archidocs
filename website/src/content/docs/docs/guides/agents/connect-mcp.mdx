Register the Archidocs MCP server with your coding agent, so it can answer architecture questions and edit the Model.

## Before you start

- The Archidocs CLI is installed. See the [Quick start](/docs/start/quick-start/).
- You are in the Workspace repo, the repo that holds the `archidocs/` folder. For another repo, see [In a code repo](#in-a-code-repo).

## 1. Register the server

The server is one command, run from the repo root. `archidocs init` prints it for your repo:

```bash
archidocs mcp --workspace archidocs
```

Pick your coding agent, and add the command where it reads MCP servers.

<Tabs syncKey="mcp-client">
<TabItem label="Claude Code">

From the repo root:

```bash
claude mcp add --scope project archidocs -- archidocs mcp --workspace archidocs
```

It writes `.mcp.json` at the repo root. Commit it, so everyone who clones the repo gets the server. Or write the file yourself:

```json title=".mcp.json"
{
  "mcpServers": {
    "archidocs": {
      "type": "stdio",
      "command": "archidocs",
      "args": ["mcp", "--workspace", "archidocs"]
    }
  }
}
```

Start `claude` in the repo and approve the server when it asks. `/mcp` lists it as connected.

</TabItem>
<TabItem label="Cursor">

Create `.cursor/mcp.json` in the repo:

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "archidocs": {
      "type": "stdio",
      "command": "archidocs",
      "args": ["mcp", "--workspace", "${workspaceFolder}/archidocs"]
    }
  }
}
```

Cursor replaces `${workspaceFolder}` with the folder that holds `.cursor/mcp.json`. The server appears under MCP in Cursor's settings, where you can turn it on or off.

</TabItem>
<TabItem label="VS Code / Copilot">

Create `.mcp.json` at the repo root:

```json title=".mcp.json"
{
  "mcpServers": {
    "archidocs": {
      "type": "stdio",
      "command": "archidocs",
      "args": ["mcp", "--workspace", "archidocs"]
    }
  }
}
```

Claude Code reads the same file. Run **MCP: List Servers** from the Command Palette to start the server and see its state.

</TabItem>
<TabItem label="Codex">

Create `.codex/config.toml` in the repo:

```toml title=".codex/config.toml"
[mcp_servers.archidocs]
command = "archidocs"
args = ["mcp", "--workspace", "archidocs"]
```

Codex reads a project's `.codex/config.toml` only once you trust the project. To add the server for every project instead, run this, which writes `~/.codex/config.toml`:

```bash
codex mcp add archidocs -- archidocs mcp --workspace archidocs
```

In the `codex` TUI, `/mcp` lists the server.

</TabItem>
</Tabs>

If the CLI isn't installed globally, run it with npx: set `"command"` to `"npx"` and start `args` with `"-y", "archidocs"`.

## Check it worked

Ask the agent something the Model knows, such as "what breaks if the Orders DB goes down?". It calls [`get_impact`](/docs/reference/mcp/get_impact/) and answers from the Model, with the Owners of the Elements it lists.

## If it didn't

If the server fails to start, run its command yourself from the repo root:

```bash
archidocs mcp --workspace archidocs
```

When the path is wrong, it prints why and exits:

```text
archidocs: No workspace.yaml found in this folder, its archidocs/ folder, or any folder above.
```

Correct `--workspace` in your config: it is relative to the folder the coding agent starts the server in, usually the repo root. When the command works, it waits for input with no output. Stop it with Ctrl+C.

## In a code repo

An agent working on a Service's code can keep the Model in step from there. Clone the Workspace repo beside the code repo, and register the same command with `--workspace` pointing at that checkout:

```bash
archidocs mcp --workspace ../architecture/archidocs
```

In `args`, that is `["mcp", "--workspace", "../architecture/archidocs"]`. `archidocs init --skill --workspace ../architecture/archidocs` installs the skill in the code repo and prints the same command. See [Install the agent skill](/docs/guides/agents/install-skill/).

## From a published site, read-only

To answer questions without a checkout, serve the Bundle a published viewer site holds:

```bash
archidocs mcp --bundle https://architecture.example.com/workspace.bundle.json --viewer-url https://architecture.example.com/
```

Only the read tools are offered. The server re-reads the site's Revision index at most once a minute, so it follows new deploys. With `--viewer-url`, results link to the same View in the published viewer.

## Over HTTP

For a coding agent that connects to a URL instead of starting a process, start the server yourself:

```bash
archidocs mcp --http --port 3737 --workspace archidocs
```

It listens on `http://127.0.0.1:3737/mcp` only, and leaves the write tools off unless you add `--allow-writes`. Register the URL:
