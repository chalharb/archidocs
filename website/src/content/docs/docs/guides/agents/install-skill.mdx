Install the `archidocs-authoring` skill, so a coding agent loads the authoring guide before it edits the Model.

Other skills build on authoring, each with a guide of its own. The `archidocs-fill-gaps` skill finds what the Model leaves empty and interviews you to fill it. An agent loads its guide with `get_guide("fill-gaps")`, and that guide has it load the authoring guide first. See [Fill documentation gaps](/docs/guides/agents/fill-gaps/).

## Before you start

- The Archidocs CLI is installed. See the [Quick start](/docs/start/quick-start/).
- You know what the skill and the guide are for. See [Agents and MCP](/docs/concepts/agents-and-mcp/).

## 1. Install it in the Workspace repo

`archidocs init` installs the skill with the Workspace. From the repo root:

```bash
archidocs init
```

```text
Wrote archidocs/workspace.yaml
Updated .gitignore
Wrote .agents/skills/archidocs-authoring/SKILL.md
Wrote .claude/skills/archidocs-authoring/SKILL.md
Wrote .github/skills/archidocs-authoring/SKILL.md
Updated AGENTS.md
Wrote .mcp.json

Check the server your coding agent will start:

  archidocs mcp --workspace archidocs --check
```

It writes the skill into each folder where coding agents look for skills. It adds an "Architecture model" section to `AGENTS.md`, and to `CLAUDE.md` if there is one. It registers the MCP server in `.mcp.json`, as [Connect an agent over MCP](/docs/guides/agents/connect-mcp/) explains.

## 2. Install it in a code repo

Skip this step unless agents edit the Model from a repo that holds code, not the Workspace. Clone the Workspace repo beside it, then run this in the code repo:

```bash
archidocs init --skill --workspace ../architecture/archidocs
```

```text
Wrote .agents/skills/archidocs-authoring/SKILL.md
Wrote .claude/skills/archidocs-authoring/SKILL.md
Wrote .github/skills/archidocs-authoring/SKILL.md
Updated AGENTS.md
Wrote .mcp.json

Check the server your coding agent will start:

  archidocs mcp --workspace ../architecture/archidocs --check

Point --workspace at a local checkout of the Workspace repo, relative to where the coding agent starts the server.
```

`--workspace` is the path to the Workspace checkout, written into the code repo's `.mcp.json`. See [Connect an agent over MCP](/docs/guides/agents/connect-mcp/#in-a-code-repo).

## 3. Keep it current

Run `archidocs init` again after upgrading the CLI. It rewrites the skill files if they changed and leaves everything else alone.

## Check it worked

Ask the agent to add a Service. It loads the authoring guide first, with the MCP [`get_guide`](/docs/reference/mcp/get_guide/) tool or `archidocs guide --skill authoring`. Servers older than `get_guide` serve the same guide as [`get_authoring_guide`](/docs/reference/mcp/get_authoring_guide/), which the skill names as a fallback.

To read what it reads, run the same command:

```bash
archidocs guide --skill authoring
```

`--skill` defaults to `authoring`, so `archidocs guide` prints the same.

The first lines are the skill's name and description:

```text
---
name: archidocs-authoring
description: Edit the Archidocs architecture Model. Use when bootstrapping a Project from code, adding or changing Services, Relationships, Deployments or Views, or proposing an ADR.
---
```

`archidocs guide <topic>` prints one task, such as [`add-service`](/docs/reference/agent-guide/add-service/). `archidocs guide --skill fill-gaps` prints the [`fill-gaps`](/docs/reference/agent-guide/fill-gaps/) skill's guide, the same as `get_guide("fill-gaps")`. The guides for the latest release are also under [Authoring guide for agents](/docs/reference/agent-guide/).
