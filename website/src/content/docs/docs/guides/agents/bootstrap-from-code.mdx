Have a coding agent read an existing codebase and declare its whole Project in one pass, with you approving what it found before it writes anything.

:::note[For agents]
The agent topic for this task is [`bootstrap`](/docs/reference/agent-guide/bootstrap/).
:::

## Before you start

- The agent can read the code, and has the Archidocs MCP server over a writable [Workspace checkout](/docs/reference/glossary/#term-checkout). See [Connect an agent over MCP](/docs/guides/agents/connect-mcp/).
- The skill is installed in the code repo. See [Install the agent skill](/docs/guides/agents/install-skill/).
- The Team that will own the Project, and the Environments it runs in, are in `workspace.yaml`. Or you are ready to add them.

## 1. Ask for it

Start the agent in the code repo and name the Project and its Team:

```text
Bootstrap the Archidocs Project "orders" for the Orders Team from this repo.
```

The skill sends the agent to the `bootstrap` topic, which it follows from here.

## 2. Review the inventory

The agent reads Dockerfiles, manifests, Terraform, HTTP clients, connection strings and topic names. It shows a table of the Services, Components, Relationships, Deployment Targets and Deployments it found, each with its evidence (file and line) and its confidence.

It asks only what code can't tell: how Services group into Systems, which are External, the business descriptions, and Owners other than the Project's. Edit the table until it is right, then approve it. That one approval covers the writes.

## 3. Let it write

The agent creates the Project and writes through the MCP write tools, in dependency order. Each write is checked as it is made, so the Model is valid at every step.

A Relationship to another Team's Service is resolved by name, URL or host to its Qualified id. When the provider isn't in the Model yet, the agent leaves the Relationship out and lists it as a gap for that Team.

## 4. Review the pull request

The agent finishes with `check` and a report of what it wrote and skipped, with evidence, ready for the pull request description. Commit, push, and review it like code.

## Check it worked

In the Workspace checkout:

```bash
archidocs check
```

```text
0 errors, 0 warnings
```

Then run `archidocs diff main` to list every Element and Relationship the agent added. A [PR preview](/docs/guides/publish/pr-previews/) shows them on the diagrams.

## If it didn't

If the agent writes YAML files by hand instead of calling the write tools, it isn't connected to the MCP server. Check the server is registered, as [Connect an agent over MCP](/docs/guides/agents/connect-mcp/) shows.

If a write is refused, the agent gets the rule and the file and line. It fixes the input or asks you, then writes again.
