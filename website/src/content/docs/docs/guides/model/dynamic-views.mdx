A Dynamic View shows one scenario, such as "a customer signs in", as numbered Steps drawn as a sequence chart. Every Step follows a Relationship in the Model, so the scenario can't show a call the architecture doesn't have.

:::note[For agents]
The agent topic for this task is [`dynamic-view`](/docs/reference/agent-guide/dynamic-view/).
:::

## 1. Trace the scenario

Start from who or what begins it, and follow the Relationships: in the viewer, the Element panel lists each Element's Relationships, and the **Connect to…** Lens shows the paths between two. Where the Model has no Relationship for a Step that happens, [add the Relationship](/docs/guides/model/connect-services/) first.

## 2. Write the Steps

Add the View under `views` › `dynamic` in a Project's `views.yaml`:

```yaml file="examples/big-bank/archidocs/digital/views.yaml" region="sign-in"
```

<Diagram view="big-bank/digital:sign-in" alt="A Big Bank customer signs in: the Single-Page Application, the Sign In Controller and the Security Component validate a token with the Auth Service, and the replies come back." />

Each Step is one of:

- **A call**: `from` the consumer `to` the provider of a Relationship, or of an edge derived from one, as `spa` to `sign-in-controller`.
- **A reply**: `return: true`, `from` the provider back `to` the consumer of a sync Relationship.
- **An event**: `from` the Publisher `to` a Subscriber, over the Subscriber's `via` subscription. It is drawn the way the event travels, though the Relationship points the other way.

When two Relationships connect the same pair, name one with `relationship: <id>`. `participants` fixes the order of the lifelines; otherwise they appear in the order they are first used.

## 3. Check it

```bash
archidocs check
```

A Step needs a Relationship to follow. A reply written as a call has none:

```yaml file="website/samples/step-without-relationship/archidocs/shop/views.yaml" fails="missing-step"
```

`archidocs check` reports [`missing-step`](/docs/reference/rules/missing-step/), because nothing declares that `api` depends on `web`. The second Step is the reply to the first, so it needs `return: true`.

In the viewer, the View opens as the sequence chart, with its Steps listed beside it: select a Step to follow it, or switch to the graph of numbered Steps.

## With an agent

[`upsert_view`](/docs/reference/mcp/write-tools/#upsert_view) writes a Dynamic View when its definition has `steps`, and [`find_paths`](/docs/reference/mcp/read-tools/#find_paths) helps trace one.
