A Deployment is one Service in one Environment on one Deployment Target, and it holds the Service's URL there. See [Deployments](/docs/concepts/deployments/) for the idea.

:::note[For agents]
The agent topic for this task is [`deployments`](/docs/reference/agent-guide/deployments/).
:::

## 1. Check the Environment exists

Environments are defined once, in `workspace.yaml`, and shared by every Project. Add one only after agreeing it with the other Teams.

## 2. Declare the Targets

Under `targets`, declare where Services run: a `name` and a `kind` (`region`, `cluster`, `namespace`, `platform`, or whatever fits), nested as they nest. Usually one Team, such as a platform Team, declares the shared ones:

```yaml file="examples/big-bank/archidocs/platform/targets.yaml"
```

Other Projects use them by Qualified id, as `platform:eks-prod`. A Target has its own Owner, the Project's Team unless `owner` says otherwise.

## 3. Add the Deployments

Under `deployments`, add one entry per Service per Environment and Target, with its `url`, and any further named URLs as `endpoints`:

```yaml file="examples/big-bank/archidocs/platform/deployments.yaml"
```

A Service that doesn't serve HTTP, such as a database, has no `url`. Kafka has an endpoint for its bootstrap servers instead.

The `environment` must be defined in `workspace.yaml`. A near miss is caught:

```yaml file="website/samples/unknown-environment/archidocs/shop/deployments.yaml" fails="unknown-environment"
```

`archidocs check` reports [`unknown-environment`](/docs/reference/rules/unknown-environment/) and suggests `prod`.

## 4. Check it

```bash
archidocs check
```

In the viewer, select the Service and use **Where is it deployed?**, or open the Environment's Deployment View, `deployment/prod`.

## With an agent

[`upsert_target`](/docs/reference/mcp/write-tools/#upsert_target) and [`upsert_deployment`](/docs/reference/mcp/write-tools/#upsert_deployment) write them; [`upsert_environment`](/docs/reference/mcp/write-tools/#upsert_environment) adds an Environment.
