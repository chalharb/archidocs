Add a [Deployment](/docs/reference/glossary/#term-deployment), one Service in one Environment on one Deployment Target, so readers find where the Service runs and its URL there.

:::note[For agents]
The agent topic for this task is [`deployments`](/docs/reference/agent-guide/deployments/).
:::

## Before you start

- The Service is in the Model. See [Add a Service](/docs/guides/model/add-a-service/).
- The Environment is defined in `workspace.yaml`. Every Project shares it, so agree a new one with the other Teams first. See [`environments`](/docs/reference/model/workspace-yaml/#environments).

## 1. Declare the Deployment Targets

Under `targets`, declare where Services run, nested as they nest. A platform Team usually declares the shared ones:

```yaml file="examples/big-bank/archidocs/platform/targets.yaml"
```

Other Projects use a Target by its Qualified id, as `platform:eks-prod`. Every field is in the [`targets` reference](/docs/reference/model/deployments-yaml/#targets).

## 2. Add the Deployments

Under `deployments`, add one entry per Service, Environment and Target, with its `url`:

```yaml file="examples/big-bank/archidocs/platform/deployments.yaml"
```

A Service that serves no HTTP, such as a database, has no `url`. The other fields, such as `endpoints`, are in the [`deployments` reference](/docs/reference/model/deployments-yaml/#deployments).

## 3. Check the Workspace

```bash
archidocs check
```

```text
0 errors, 0 warnings
```

## Check it worked

Run `archidocs dev`, select the Service and use **Where is it deployed?**. Or open the Environment's Deployment View, such as `deployment/prod`.

## If it didn't

`check` catches an `environment` that `workspace.yaml` doesn't define:

```yaml file="website/samples/unknown-environment/archidocs/shop/deployments.yaml" fails="unknown-environment"
```

```text
archidocs/shop/deployments.yaml:7:18  error  unknown-environment  Unknown Environment "production"; did you mean "prod"?

1 error, 0 warnings

Rule docs:
  unknown-environment  https://archidocs.dev/docs/reference/rules/unknown-environment/
```

That is [`unknown-environment`](/docs/reference/rules/unknown-environment/): use the name it suggests.

`check` reports [`unknown-target`](/docs/reference/rules/unknown-target/) when `target` names no Deployment Target. Check the Qualified id.

## With an agent

[`upsert_target`](/docs/reference/mcp/write-tools/#upsert_target) and [`upsert_deployment`](/docs/reference/mcp/write-tools/#upsert_deployment) write them. [`upsert_environment`](/docs/reference/mcp/write-tools/#upsert_environment) adds an Environment.
