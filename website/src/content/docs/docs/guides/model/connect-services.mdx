Declare a [Relationship](/docs/reference/glossary/#term-relationship), one Element's dependency on another, so the viewer and agents know what depends on what.

:::note[For agents]
The agent topic for this task is [`relationships`](/docs/reference/agent-guide/relationships/).
:::

## Before you start

- The consumer is in the Model. See [Add a Service](/docs/guides/model/add-a-service/).
- The provider is in the Model, in your Project or another. See [Relationships](/docs/concepts/relationships/) for which way a Relationship points.

## 1. Declare the Relationship under the consumer

Add a `relationships` entry under the consumer, with `to` naming the provider. Name a provider in another Project by its Qualified id, `project:id`, as `core:mainframe` here:

```yaml file="examples/big-bank/archidocs/payments/model.yaml" region="payments-service"
```

Write the `description` as a verb phrase that completes "consumer … provider". The other fields are in the [Relationship reference](/docs/reference/model/model-yaml/#relationship).

## 2. Declare an event under the Subscriber

Skip this step for a call. For an event, declare the Relationship under the Subscriber, pointing `to` the Publisher. Add `interaction: async`, the broker Service as `via`, and the topic as `channel`:

```yaml file="examples/big-bank/archidocs/payments/model.yaml" region="fraud-detection"
```

## 3. Check the Workspace

```bash
archidocs check
```

```text
0 errors, 0 warnings
```

## Check it worked

Run `archidocs dev` and select the consumer. The Element panel lists the new Relationship, and the Views that show both ends draw it.

## If it didn't

`check` refuses `via` and `channel` on a Relationship without `interaction: async`:

```yaml file="website/samples/sync-subscription/archidocs/shop/model.yaml" fails="via-on-sync"
```

```text
archidocs/shop/model.yaml:12:9  error  via-on-sync  `via` is only for an async Relationship; add `interaction: async` or remove `via`
archidocs/shop/model.yaml:13:9  error  via-on-sync  `channel` is only for an async Relationship; add `interaction: async` or remove `channel`

2 errors, 0 warnings

Rule docs:
  via-on-sync  https://archidocs.dev/docs/reference/rules/via-on-sync/
```

That is [`via-on-sync`](/docs/reference/rules/via-on-sync/): add `interaction: async`.

`check` reports [`unknown-element`](/docs/reference/rules/unknown-element/) when `to` names an id that isn't in the Model. Correct the id, or write the Qualified id of a provider in another Project. If the provider isn't in the Model yet, leave the Relationship out and tell the provider's Team.

`check` reports [`via-not-broker`](/docs/reference/rules/via-not-broker/) when `via` names a Service that isn't `type: broker`.

## With an agent

[`upsert_relationship`](/docs/reference/mcp/write-tools/#upsert_relationship) adds or updates a Relationship. [`search_elements`](/docs/reference/mcp/read-tools/#search_elements) resolves a provider's name, URL or host to its Qualified id.
