Publish the viewer to GitLab Pages from GitLab CI, checked and rebuilt on every push to the default branch.

## Before you start

- The Workspace is in a GitLab project, and `archidocs check` passes. See the [Quick start](/docs/start/quick-start/).
- GitLab Pages is available on the project.

## 1. Include the template

Add the Archidocs GitLab CI template to `.gitlab-ci.yml`:

```yaml title=".gitlab-ci.yml"
include:
  - remote: https://raw.githubusercontent.com/chalharb/archidocs/v1/templates/gitlab/archidocs.gitlab-ci.yml
    inputs:
      images: true
```

It adds a `pages` job, for pushes to the default branch and tags, and an `archidocs-preview` job for merge requests. Every input, such as `working-directory`, `keep` and `version`, is in the [GitLab template reference](/docs/reference/ci/gitlab-template/#inputs).

## 2. Push

Commit `.gitlab-ci.yml` and push it to the default branch.

## Check it worked

Open the pipeline in the project's **Build › Pipelines**. When the `pages` job succeeds, **Deploy › Pages** shows the site's URL. Open it: the viewer starts on the C2 Landscape.

## If it didn't

If `archidocs check` fails, the `pages` job stops and publishes nothing, so the last good site stays up. The job's log shows the file, the line and the rule, with a link to the [rule's page](/docs/reference/rules/). Fix it and push again.

If the viewer shows only the latest Revision, the job's clone is shallow. The template sets `GIT_DEPTH: 0`; check that your `.gitlab-ci.yml` doesn't override it.
