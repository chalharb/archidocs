In about five minutes you go from an empty repo to the viewer showing a small Model: a Shopper who uses an Online Shop made of two Services. Every file you need is on this page.

## 1. Install the CLI

Archidocs needs Node.js 22.18 or later.

<Tabs syncKey="package-manager">
<TabItem label="npm">

```bash
npm install --global archidocs
```

</TabItem>
<TabItem label="pnpm">

```bash
pnpm add --global archidocs
```

</TabItem>
<TabItem label="npx">

There is nothing to install. Put `npx` before each command on this page, as in `npx archidocs check`.

</TabItem>
</Tabs>

## 2. Create a Workspace

A [Workspace](/docs/reference/glossary/#term-workspace) is one git repo that holds the whole architecture. In the repo that will hold yours (a new, empty one is fine), run:

```bash
archidocs init
```

This writes a starter `archidocs/workspace.yaml`, adds the `.archidocs/` cache to `.gitignore`, and installs an authoring skill for coding agents. Everything Archidocs reads lives under `archidocs/`.

## 3. Add three files

Save each file at the path in its title.

`workspace.yaml` defines the Teams that own things and the Environments that Services run in. Replace the starter file with:

```yaml file="examples/quick-start/archidocs/workspace.yaml" title="archidocs/workspace.yaml"
```

A [Project](/docs/reference/glossary/#term-project) is one Team's folder in the Workspace. Its `project.yaml` names the Team that owns everything in the folder:

```yaml file="examples/quick-start/archidocs/shop/project.yaml" title="archidocs/shop/project.yaml"
```

Every other `.yaml` file in the folder declares Elements and their Relationships. This one declares a Person, and a System that holds two Services:

```yaml file="examples/quick-start/archidocs/shop/model.yaml" title="archidocs/shop/model.yaml"
```

Each Relationship sits under the Element that depends on the other one, and its `description` reads as a sentence: "Web places orders through API".

## 4. Check it

```bash
archidocs check
```

```text
0 errors, 0 warnings
```

`archidocs check` validates every file and every reference between them. When something is wrong, it names the file, the line and the [rule](/docs/reference/rules/) that was broken.

## 5. Open the viewer

```bash
archidocs dev
```

Open `http://localhost:4321`. The viewer starts on the C2 Landscape, which shows the Shopper and the Online Shop:

<Diagram view="quick-start/c2" alt="The C2 Landscape of the quick start's Workspace: the Shopper, with an arrow to the Online Shop System." />

In the viewer, the Online Shop box has an arrow button. Select it to open the System's own View, with the two Services inside it:

<Diagram view="quick-start/c2/shop:online-shop" alt="The Online Shop System opened: the Shopper uses Web, and Web places orders through API. Both Services sit inside Online Shop." />

That is the Model you wrote, drawn. The viewer reloads as you edit the files; stop it with Ctrl+C.
